# ShiftMate 화면·하단 내비게이션 수정 방향

## 상태와 목표

2026-11-10 작성한 권장안을 사용자 후속 승인으로 **구현했다**. 최신 정책은 ADR-0038과 PROJECT_CONTEXT의 구현 절을 따른다. 아래 본문은 당시 제안 기준이며 구현 결과는 문서 끝에 기록한다. 근무 타입 추가/편집은 2026-11-11 후속 사용자 승인으로 ADR-0041의 요약 미리보기·시간 지정 스위치·하단 저장 구조로 재설계했다. 해당 화면의 최신 동작은 PROJECT_CONTEXT 상단 구현 절을 따른다. [디자인 검토](UI_DESIGN_AUDIT_2026-11-10.md)의 내부 일관성과 모바일 관례를 같은 비중으로 반영한다. 아래 수치는 변경 후 목표이며 현재 구현값이나 실기기 검증 결과가 아니다. 이 문서 작성으로 기존 ADR을 대체하지 않는다.

방향: **현재의 밝고 부드러운 인상은 유지하고, 이동 구조와 읽기·입력 크기를 통일한다.** 기존 파란색 `#0061A4`, 배경 `#F8F9FB`, Cafe24 폰트, 흰 카드, Cupertino 구조가 출발점이다. 달력 날짜/근무 코드처럼 정보 밀도가 필요한 영역은 일반 입력 폼과 구분한다.

## 1. 하단 바: 고정된 세 개의 탭

현재는 메인의 `친구 / 오늘 날짜 / 알림`과 친구 화면의 `친구 리스트 / 그룹 방`이 같은 모양을 사용한다. 아래처럼 역할을 정리한다.

| 위치 | 제안 내용 | 동작 |
|---|---|---|
| 공통 하단 탭 | 캘린더 · 친구 · 알림 | 최상위 영역을 이동한다. 항목과 순서는 유지한다. |
| 캘린더 월 헤더 | 이전 / 연월 / 다음 + 오늘 | 오늘은 선택일과 보이는 달을 오늘로 이동한다. 좁으면 헤더를 두 줄로 배치한다. |
| 친구 화면 상단 | 친구 · 그룹 세그먼트 | 같은 관계 영역 안에서 목록을 전환한다. 친구 탭 선택 상태는 유지한다. |
| 캘린더 상단 우측 | 설정 아이콘 | 현재 설정 진입점을 유지한다. |
| 각 화면 상단·본문 | 친구 추가, 그룹 생성, 근무/일정 추가 | 해당 화면의 작업 버튼으로 제공한다. |

- 외형: 하나의 흰색 바 위에 **아이콘 위·라벨 아래**, 세 칸 동일 너비. 개별 테두리 pill과 가운데 원형 날짜 버튼을 제거한다. 상단 경계는 얇게 표현하고 과한 그림자·장식은 추가하지 않는다.
- 선택: 파란 아이콘/라벨과 선택 상태 의미 정보를 함께 제공한다. 비선택은 읽을 수 있는 회색. 알림은 기존 미읽음 수/99+ 배지를 유지한다.
- 크기: 콘텐츠 높이 56 logical pixels를 초기 시안값으로 삼고 OS 하단 안전영역을 별도로 더한다. 각 항목 터치 영역은 최소 44×44를 목표로 한다. 글자 확대 시 높이가 늘어날 수 있게 한다.
- 반응: 모든 탭/버튼에 눌림 피드백을 제공한다. 화면 하단에 별도 16px 빈 띠를 중복으로 더하지 않고, 바가 차지하는 공간을 레이아웃에서 확보해 마지막 콘텐츠가 가려지지 않게 한다.
- 상태: 캘린더에서 다른 탭을 갔다 와도 선택 날짜·보이는 달을 유지한다. 친구/그룹 선택과 목록 위치도 유지한다. 캘린더 탭 재선택은 날짜를 초기화하지 않으며 오늘 이동은 명시적인 `오늘` 버튼으로만 수행한다.
- 깊이: 친구/그룹 캘린더 등 탐색 화면은 해당 탭 내부에서 push하고 뒤로가면 같은 목록 위치로 복귀한다. 생성·편집 폼은 작업에 집중하는 전체 화면/시트로 열어 탭바를 숨기고 취소·저장으로 복귀한다. 설정은 현재처럼 별도 push 화면으로 연다.
- 알림 진입: 푸시를 눌렀을 때 별도 알림 페이지를 중복 push하는 대신 알림 탭을 선택하도록 통합한다. 미완료 편집 폼이 열려 있으면 입력을 보존하고, 폼 종료 후 보류한 알림 이동을 처리한다. 로그인·프로필 완료 전에는 기존 보류 정책을 유지한다.
- 플래그: 그룹 비활성 시 현재 미리보기와 활성 시 실제 그룹 목록의 차이는 유지하며, 탭 구조 변경이 그룹 기능 활성화나 권한 확대를 의미하지 않는다.

현재 코드에서는 인증 게이트·각 소셜 로그인 완료·프로필 완료가 `CalendarPage`로 직접 진입하고 푸시는 root navigator로 `NotificationPage`를 push한다. 구현 시 이 진입점을 하나의 인증 후 탭 컨테이너로 모아야 한다. 하단 위젯 모양만 교체해서는 완성되지 않는다. 알림 탭 진입/복귀에 맞춰 기존 미읽음 갱신 시점도 옮겨야 한다.

세 탭은 현재 기능 묶음을 가장 적게 바꾸면서 최상위 이동과 화면 내 작업을 분리하는 제안이다. 그룹을 독립 탭으로 승격하거나 설정을 네 번째 탭으로 늘리는 것은 이번 범위에 필요하지 않다. 탭을 영역 이동에 사용하고 라벨을 함께 표시하는 근거는 [Apple Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)다. 외형 수치와 세 탭 구성은 이 앱을 위한 제안이다.

## 2. 공통 크기·폼 기준

| 요소 | 제안 기준 |
|---|---|
| 내비게이션 제목 | 기존 20 유지 |
| 본문·입력값·설정 행 | 16 |
| 필드 라벨·도움말 | 14, 불투명한 공용 보조 텍스트 색 |
| 탭 라벨·짧은 배지 | 12 수준, 긴 설명에 사용하지 않음 |
| 화면 좌우·카드 내부 여백 | 16 |
| 관련 요소 사이 / 섹션 사이 | 8 / 24 |
| 카드 / 입력 반경 | 기존 16 / 12 유지 |
| 입력 행·주요 버튼 | 기본 높이 48 이상, 큰 글자에서 확장 |
| 아이콘·보조 버튼 | 보이는 크기와 별개로 터치 영역 44×44 이상 목표 |

설정·근무 타입·색상의 화면 전체 0.8 배율을 역할별 토큰으로 대체한다. `AppTheme.body_medium` 등의 기존 값을 전역 변경해 달력까지 확대하지 않고, 대상 화면이 적절한 토큰을 선택하도록 정리한다. `12.8 → 16`, `20 → 16` 등 작은 화면과 큰 화면 양쪽을 같은 기준에 맞춘다.

입력은 항상 라벨을 보이고 placeholder는 예시로 사용한다. 저장은 우측 상단 `저장`, 색상 확정은 `완료`로 통일하고 같은 동작의 하단 버튼을 중복하지 않는다. 가입의 `저장하고 시작하기`는 별도 흐름이다. 값 오류는 필드 근처, 저장/통신 오류는 기존 공용 오류 방식으로 표시하며 입력을 보존한다. 저장 중에는 중복 동작을 막고 진행 상태를 보여준다.

44×44는 이 앱의 목표 터치 영역이며 모든 작은 컨트롤을 일괄적인 표준 위반으로 판단한 것은 아니다. [Apple Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)의 일반 권장 크기를 참고한다.

## 3. 화면별 변경안

| 대상 | 수정 방향 | 연결된 발견 |

| 설정 | 프로필·계정·앱·정보 등 기존 묶음을 유지하고 행 글자 16/충분한 높이로 통일. 미구현 행에는 `준비 중`을 직접 표시하고 가짜 켜짐 스위치·이동 화살표를 제거한다. 준비 중임을 알기 위한 반복 다이얼로그는 없앤다. 실제 프로필 편집·정책 링크·로그아웃·탈퇴 등 동작은 유지한다. | F02, F03 |
| 근무 타입 추가/수정 | 코드/이름 → 색상 → 근무 시간 순서의 공용 카드형 폼. 시간 없는 타입의 기존 정책 유지. 설명은 14와 충분한 대비, 색상 변경은 44 이상 터치 영역. | F03, F05, F07 |
| 색상 선택 | 선택 색상 미리보기 → 팔레트 → 직접 만들기. 선택 표시는 체크·테두리를 함께 사용한다. 전체 축소를 없애되 팔레트 수는 화면 너비에 맞춘다. | F03 |
| 커스텀 색상 | 미리보기 → 색상 휠/밝기 → 색상 코드·RGB → 최근 색상. 기본 세로 스크롤 허용. `선택한 색상`, `색상 코드`, `빨강(R)` 등 한국어 중심 라벨 사용. RGB/HEX는 첫 개선에서 계속 노출해 기능을 숨기지 않는다. | F01, F03, F08 |

## 4. 적용 순서와 완료 조건

1. **사용성 문제 우선:** 커스텀 색상 스크롤·키보드, 준비 중 설정 표현, 작은 버튼 터치 영역·안내문 대비를 먼저 바로잡는다.
2. **대표 화면 시안:** 캘린더+하단 탭, 친구+세그먼트, 설정, 근무 타입/개인 일정 폼에 공통 크기를 적용해 한 화면씩 비교한다. 확정한 기준을 색상·그룹 수정까지 적용한다.
3. **내비게이션 연결:** 탭 컨테이너와 인증/푸시 진입·상태 보존을 함께 구현한다. 단순 외형 변경과 분리해 회귀를 확인한다.
4. **완료 검증:** 아래 조건을 충족한 뒤 구현 결과와 채택한 정책을 PROJECT_CONTEXT/WORKLOG/ADR에 기록한다.

- 320×568, 390×844 및 글자 배율 1/2에서 필드·최근 색상·확정 버튼에 접근 가능. 키보드가 열린 HEX/메모 편집에서도 접근 가능.
- 날짜/시간의 필수 정보가 잘리지 않음. 일반 본문/안내문 실제 합성 대비 4.5:1 목표 충족. 버튼 영역 측정과 실기기 눌림 확인.
- 캘린더 → 친구 → 알림 → 캘린더에서 보이는 달·선택일 보존. 오늘 버튼만 날짜 초기화.
- 친구 → 그룹 → 상세 → 뒤로가기에서 섹션/목록 위치 보존. 루트 탭 중복 push 없음.
- 로그인/가입 완료/재실행은 동일한 탭 컨테이너로 진입. 로그아웃/계정 전환은 이전 계정의 탭 데이터·화면 이력을 제거.
- 푸시·알림 배지 갱신, 미완료 폼 중 푸시 보류, 그룹 플래그/권한별 동작 확인.
- 달력 2주/월 전환·근무 입력·일정 추가 기존 회귀 및 변경 Dart 분석/포맷 검사.

## 파일 역할·검증·롤백

- 역할: 구현자가 화면별 범위와 완료 조건을 참조하는 수정 방향서. 의존성은 기존 검토 보고서, `PROJECT_CONTEXT`, `AppTheme`, 현재 내비게이션 코드다. 사용 예: 하단 탭 작업 시 1절과 4절을 구현/회귀 체크리스트로 사용한다.
- 이번 검증: 기존 검토 증거 및 현재 하단 바, 메인/친구 화면, 인증/푸시 진입 코드와 제안의 영향범위를 대조했다. 외부 기준은 Apple 공식 문서, 스킬 검색은 모바일 뒤로가기 항목만 참고했다. 웹 전용 검색 결과는 적용하지 않았다.
- 이번 변경: 문서만 작성했으므로 앱 테스트·새 렌더링은 실행하지 않았다. 본문의 완료 조건은 후속 구현에 대한 요구이며 통과 결과가 아니다.
- 롤백: 이 파일과 PROJECT_CONTEXT/WORKLOG의 이번 방향 수립 항목만 제거한다. 이전 검토·스킬 설치 기록은 유지한다.
